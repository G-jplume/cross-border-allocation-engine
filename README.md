# 跨境电商分仓占比计算引擎

基于历史出单数据，为跨境电商 SKU 计算美国四仓（美西 / 美东 / 美南GA / 美南TX）的发货占比与整数落货量。

- **计算引擎**：`allocation_engine.py`（纯 Python，7 步链路）
- **Web 界面**：`app.py`（Streamlit，上传 → 参数 → 计算 → 微调 → 导出）
- **详细中文说明**：`分仓占比计算引擎_使用说明.docx`

---

## 计算链路（7 步）

```
原始数据
  → ① 运算SKU映射      合并同产品变体（VLOOKUP + "-"前缀 fallback）
  → ② 时间衰减加权      w = λ^(锚点 − 月份)，仅目标期月份
  → ③ 季节匹配因子      目标月之前 N 个月 × β（环形距离，目标月不计入）
  → ④ 自身占比          加权出单量 ÷ 加权合计
  → ⑤ 基准占比          SPU → 一级分类 → 室内外 → 全公司 回退 + 层内贝叶斯收缩
  → ⑥ 最终占比          a×自身 + (1−a)×基准 → 叠加趋势差 α → 归一化
  → ⑦ 落货量            占比 × 批量，最大余额法（整数合计精确）
```

### 参数生效层级

| 参数 | 作用层 | 说明 |
|---|---|---|
| `lambda` 衰减速度 | 原始数据加权 | 全局，所有品类 |
| `seasonal_*` 季节因子 | 原始数据加权 | 仅适用品类，与衰减相乘 |
| `alpha_trend` 趋势 α | 最终占比 | 归一化前叠加趋势差 |
| `trend_cap` 调整上限 | 最终占比 | 单仓趋势调整幅度上限 |
| `k` 收缩强度 | SKU 层混合 | 自身 vs 基准 |
| `k_cat` 品类层观测数 | 基准层混合 | 子层 vs 父层 |

> **季节因子与趋势因子作用层不同**：季节因子改的是「历史数据权重」（步骤③），趋势因子改的是「最终占比」（步骤⑥）。两者不冲突，可同时启用。

## 关键实现细节（易错点）

### 1. 衰减权重的作用域

```python
df["月份序号_py"] = df["年"] * 12 + df["月"]
dist = anchor - df["月份序号_py"]
in_target = df["在目标期"] == 1
df["衰减权重_py"] = np.where(in_target, lambda_val ** dist.clip(lower=0), 0.0)
```

**只有目标期内的月份有权重**，其余月份（含未来月份）一律为 0。这不是选型问题——如果不加 `in_target` 约束，未来月份会拿到 `λ^0 = 1` 的满权重，导致自身占比被污染。

### 2. 季节窗口方向

```python
def in_season(m, target, win):
    """窗口 = [target-win, target-1]，目标月本身不计入。"""
    d = (target - 1 - m) % 12
    return 0 <= d <= (win - 1)
```

窗口取「目标月之前 N 个月」，**不含目标月本身**。距离按环形计算，所以 1 月发货、`win=1` 时命中 12 月。
目标期 `{1,2,3}`、`win=1` → 命中 `{12, 1, 2}`，与 Excel 模板一致。

### 3. 层内贝叶斯收缩

```python
def _shrink(child_ratios, child_n, parent_ratios, k_cat):
    """k_cat 即「最小等效观测数」：把父层均值的可信度折算成 k_cat 个虚拟观测。"""
    if child_n <= 0:
        return dict(parent_ratios)
    w = child_n / (child_n + k_cat)
    return {wh: w * child_ratios[wh] + (1 - w) * parent_ratios[wh] for wh in WAREHOUSES}
```

作用于 `一级分类→全公司`、`SPU→一级分类`、`室内外→全公司`。

### 4. 趋势调整

```python
d = 近期同月各仓加权占比 - 远期同月各仓加权占比
adjusted[wh] = final[wh] + alpha * max(-cap, min(cap, d))
```

近期窗口 = 目标期平移 1 年，远期窗口 = 目标期平移 2 年（自动推导）。
`norm_method="proportional"`（默认）时调整后重新归一化，保证四仓合计 = 100%；
`norm_method="raw"` 时保留原值，与 Excel 模板 AS 列一致（合计 97%~103%）。

### 5. 最大余额法分配落货量

先 `floor(占比 × 批量)`，再把差额按小数部分从大到小补足，保证整数合计精确等于批量。

## 使用方法

### Web 界面（推荐）

```bash
streamlit run app.py
```

页面流程：**① 上传数据 → ② 开始计算 → ③ 查看结果与自动体检 → ④ 占比微调 → ⑤ 可视化 → ⑥ 导出**

### Python 调用

```python
from allocation_engine import AllocationEngine

engine = AllocationEngine(data_dir="engine_data")
engine.load_data()

engine.step1_sku_mapping()      # 运算SKU映射
engine.step2_decay_weight()     # 时间衰减加权
engine.step3_seasonal_factor()  # 季节因子
engine.step4_self_ratio()       # 自身占比
engine.step5_benchmark()        # 基准占比（含 k_cat 收缩）
df_results = engine.step6_final_ratio(demand_qty=3000)   # 趋势调整 + 最终占比 + 落货量

for name, ok, msg in engine.self_check(df_results):
    print(f"[{'OK' if ok else '!!'}] {name}: {msg}")

engine.verify(df_results)       # 与 Excel 结果对比
```

常用覆盖项：

```python
engine.params["alpha_trend"] = 0.5
engine.params["norm_method"] = "proportional"
engine.k_cat = 12.0
engine.seasonal_categories = ["庭院、草坪与花园"]   # None 则回退到 params 配置
engine.trend_recent = (24313, 24315)               # None 则按 anchor 自动推导
engine.trend_far = (24301, 24303)
```

## 自检（`self_check`）

返回 `[(项目, 是否通过, 说明)]`，覆盖三个易错点：

| 检查项 | 通过标准 | 失败含义 |
|---|---|---|
| 最终占比四仓合计 = 100% | 最大偏差 < 1e-9 | 归一化异常 |
| 调整后占比四仓合计 = 100% | 最大偏差 < 1e-9 | 归一化异常 |
| 季节因子命中行数 | > 0 | 适用品类与数据「一级分类」不匹配，季节因子静默失效 |
| 趋势因子 α 生效 | 有 SKU 取到趋势差 | 历史数据不足以覆盖去年同期 |

## 常见问题（FAQ）

### Q1：季节匹配因子是默认按「庭院、草坪与花园/庭院」来，还是基于上传数据判断？

**混合模式**。上传数据后，系统从「一级分类」列提取所有唯一品类作为可选项，自动勾选其中名为「庭院、草坪与花园」和「庭院」的品类作为默认值。可手动增删。如果上传数据不包含这两个品类名，则默认不勾选任何品类，季节因子不生效。

### Q2：趋势因子和季节匹配因子作用一致吗？需要都保留吗？

**两者作用层级不同，不冲突，建议都保留。**

| | 季节匹配因子 | 趋势因子 |
|---|---|---|
| 作用步骤 | ③ 加权层 | ⑥ 最终占比层 |
| 做什么 | 放大同季历史数据的**权重** | 叠加年度趋势**差**到最终占比 |
| 影响范围 | 仅适用品类 | 全局（有趋势数据的SKU） |
| 关键参数 | β、N | α、调整上限 |

季节因子让预测贴近去年同期的数据分布，趋势因子让预测跟随年度变化方向。两者互补。

### Q3：「品类层最小等效观测数」默认值12代表什么含义？

贝叶斯收缩参数，公式为 `子层权重 = n / (n + k_cat)`，n = 该层目标期实际观测行数。

| 观测行数 n | 子层权重 | 父层权重 | 含义 |
|---|---|---|---|
| n = 4 | 25% | 75% | 数据太少，大部分用父层均值 |
| n = 12 | 50% | 50% | 临界点，子层和父层各半 |
| n = 88 | 88% | 12% | 数据充足，信任子层自身 |

k_cat 越大越保守——子层样本少时更快被拉向上层均值。

### Q4：「季节增强倍数」默认值3.0代表什么含义？

β=3.0 表示落在季节窗口内的历史数据，其权重被**放大3倍**。例如原始衰减权重0.5 → 放大后1.5。非季节性品类数据权重不变（×1.0）。

### Q5：4个仓库的占比加起来必须等于100%，能实现吗？

**已实现，三层保障**：

1. 引擎层：Step6 计算完最终占比后自动归一化
2. 侧边栏开关：「归一化（四仓合计=100%）」默认开启
3. 微调区：改一个仓的占比，其余三仓按原比例自动补足
4. 自检：验证合计偏差 < 1e-9

落货量使用最大余额法，保证整数合计精确等于发运批量。

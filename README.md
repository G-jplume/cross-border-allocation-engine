# 跨境电商分仓占比计算引擎

基于历史出单数据，为跨境电商 SKU 计算美国四仓（美西 / 美东 / 美南GA / 美南TX）的发货占比与整数落货量。

- **在线使用**：Streamlit Cloud 部署，浏览器直接访问
- **计算引擎**：`allocation_engine.py`（纯 Python，7 步链路）
- **Web 界面**：`app.py`（Streamlit，上传 → 参数 → 计算 → 微调 → 导出）

---

## 计算链路（7 步）

```
原始数据
  → ① 运算SKU映射      合并同产品变体（映射表 + "-"前缀 fallback）
  → ② 时间衰减加权      w = λ^(锚点 − 月份)，仅目标期月份
  → ③ 季节匹配因子      目标月之前 N 个月 × β（环形距离，目标月不计入）
  → ④ 自身占比          加权出单量 ÷ 加权合计
  → ⑤ 基准占比          SPU → 一级分类 → 室内外 → 全公司 回退 + 层内贝叶斯收缩
  → ⑥ 最终占比          a×自身 + (1−a)×基准 → 叠加趋势差 α → 归一化
  → ⑦ 落货量            占比 × 批量，最大余额法（整数合计精确）
```

## 参数说明

### 侧边栏参数一览

| 分组 | 参数 | 默认值 | 作用层 | 说明 |
|---|---|---|---|---|
| ① 目标发货月份 | 起始月 / 结束月 | 1 / 3 | 全局 | 发哪几个月的货，系统只统计这段月份的历史数据 |
| ① 目标发货月份 | 目标年份 | 2027 | 全局 | 锚点 = 目标期中间月份的 年×12+月 |
| ② 时间衰减 | 衰减速度 λ | 0.85 | 加权层 | 每月权重乘以 λ。0.85=每月衰减15%；1.0=不衰减 |
| ③ 季节匹配 | 启用开关 | 开 | 加权层 | 开启后对选定品类放大同季数据权重 |
| ③ 季节匹配 | 增强倍数 β | 3.0 | 加权层 | 同季节数据权重 × β。3.0=放大3倍；1.0=不增强 |
| ③ 季节匹配 | 窗口范围 N | 1 | 加权层 | 目标月之前 N 个月（环形距离，目标月不计入） |
| ③ 季节匹配 | 适用品类 | 庭院类 | 加权层 | 从上传数据「一级分类」自动生成，默认勾选庭院类 |
| ④ 趋势因子 | 趋势因子 α | 0.3 | 最终占比层 | 趋势差 × α 叠加到最终占比。0=关闭 |
| ④ 趋势因子 | 单仓调整上限 | ±5% | 最终占比层 | 每个仓库趋势调整幅度不超过此值 |
| ④ 趋势因子 | 归一化开关 | 归一化 | 最终占比层 | 趋势调整后四仓合计是否缩放到 100% |
| ⑤ 新品与基准 | 新品阈值 | 2月 | SKU层混合 | 历史出单月数 ≤ 此值时完全使用基准 |
| ⑤ 新品与基准 | 收缩强度 k | 6 | SKU层混合 | 自身权重 = n/(n+k)，n=目标期月数 |
| ⑤ 新品与基准 | 权重上下限 | 0.0 / 0.9 | SKU层混合 | 自身数据的最低/最高权重 |
| ⑤ 新品与基准 | 品类层最小等效观测数 | 12 | 基准层收缩 | 子层权重 = n/(n+k_cat)，n=该层观测行数 |

### 季节因子 vs 趋势因子

两者作用层级不同，不冲突，可同时启用：

| | 季节匹配因子 | 趋势因子 |
|---|---|---|
| 作用步骤 | ③ 加权层 | ⑥ 最终占比层 |
| 做什么 | 放大同季历史数据的**权重** | 叠加年度趋势**差**到最终占比 |
| 影响范围 | 仅适用品类 | 全局（有趋势数据的SKU） |
| 关键参数 | β、N | α、调整上限 |

季节因子让预测贴近去年同期的数据分布，趋势因子让预测跟随年度变化方向。两者互补。

## 页面操作流程

### Web 界面

页面流程：**① 上传数据 → ② 开始计算 → ③ 查看结果与自动体检 → ④ 占比微调 → ⑤ 可视化 → ⑥ 导出**

#### 1. 上传数据
- 上传原始出单数据（CSV 或 Excel），必须包含列：源SKU、SPU、室内外、一级分类、年、月、美西、美东、美南GA、美南TX
- 或点击「使用示例数据」用内置数据演示
- 可点击「下载模板」获取 CSV 模板
- 上传后展开「数据体检 + 预览」查看总行数、SKU数、品类数、时间跨度、重复记录检测

#### 2. 混用SKU映射（可选）
- 展开折叠器上传映射表（CSV 或 Excel，需含「源SKU」和「相似SKU」两列）
- 不上传也能算：未映射的 SKU 自动取「-」前部分合并

#### 3. 开始计算
- 点击「开始计算」按钮，引擎执行 7 步链路
- 计算完成后显示运算SKU总数和各仓库平均占比

#### 4. 查看结果
- **自动体检**：验证占比合计、季节命中、趋势生效
- **SKU级表格**：可按单个SKU或品类筛选，展示自身/基准/最终/趋势差/调整后占比
- **聚合层级**：按一级分类、室内外、SPU、全公司聚合的分仓占比

#### 5. 占比微调
- 选择要微调的SKU，直接修改四仓占比
- 点击「按改动自动补足到100%」，其余三仓按原比例自动补足
- 输入发运批量，按占比生成落货量（最大余额法保证整数精确）

#### 6. 可视化
- 选择SKU查看饼图和柱状图
- 全SKU分仓占比堆叠图（前50个SKU）

#### 7. 导出结果
- 下载 Excel（含SKU级 + 聚合层级）
- 下载 CSV（SKU级）
- 下载 CSV（一级分类）

## 常见问题（FAQ）

### Q1：季节匹配因子是默认按「庭院、草坪与花园/庭院」来，还是基于上传数据判断？

混合模式。上传数据后，系统从「一级分类」列提取所有唯一品类作为可选项，自动勾选其中名为「庭院、草坪与花园」和「庭院」的品类作为默认值。可手动增删。如果上传数据不包含这两个品类名，则默认不勾选任何品类，季节因子不生效。

### Q2：趋势因子和季节匹配因子作用一致吗？需要都保留吗？

两者作用层级不同，不冲突，建议都保留：

| | 季节匹配因子 | 趋势因子 |
|---|---|---|
| 作用步骤 | ③ 加权层 | ⑥ 最终占比层 |
| 做什么 | 放大同季历史数据的**权重** | 叠加年度趋势**差**到最终占比 |
| 影响范围 | 仅适用品类 | 全局（有趋势数据的SKU） |
| 关键参数 | β、N | α、调整上限 |

季节因子让预测贴近去年同期的数据分布，趋势因子让预测跟随年度变化方向。两者互补。

### Q3：「品类层最小等效观测数」默认值12代表什么含义？

贝叶斯收缩参数，公式为 `子层权重 = n / (n + k_cat)`，n = 该层目标期实际观测行数。

| 观测行数 n | 子层权重 | 父层权重 | 含义 |
|---|---|---|---|
| n = 4 | 25% | 75% | 数据太少，大部分用父层均值 |
| n = 12 | 50% | 50% | 临界点，子层和父层各半 |
| n = 88 | 88% | 12% | 数据充足，信任子层自身 |

k_cat 越大越保守——子层样本少时更快被拉向上层均值。

### Q4：「季节增强倍数」默认值3.0代表什么含义？

β=3.0 表示落在季节窗口内的历史数据，其权重被**放大3倍**。例如原始衰减权重0.5 → 放大后1.5。非季节性品类数据权重不变（×1.0）。

### Q5：4个仓库的占比加起来必须等于100%，能实现吗？

已实现，四层保障：

1. 引擎层：Step6 计算完最终占比后自动归一化
2. 侧边栏开关：「归一化（四仓合计=100%）」默认开启
3. 微调区：改一个仓的占比，其余三仓按原比例自动补足
4. 自检：验证合计偏差 < 1e-9

落货量使用最大余额法，保证整数合计精确等于发运批量。

## 自检（`self_check`）

计算完成后自动执行，覆盖三个易错点：

| 检查项 | 通过标准 | 失败含义 |
|---|---|---|
| 最终占比四仓合计 = 100% | 最大偏差 < 1e-9 | 归一化异常 |
| 调整后占比四仓合计 = 100% | 最大偏差 < 1e-9 | 归一化异常 |
| 季节因子命中行数 | > 0 | 适用品类与数据「一级分类」不匹配，季节因子静默失效 |
| 趋势因子 α 生效 | 有 SKU 取到趋势差 | 历史数据不足以覆盖去年同期 |

## 使用方法

### Web 界面（推荐）

访问 Streamlit Cloud 部署地址，或在本地运行：

```bash
streamlit run app.py
```

### Python 调用

```python
from allocation_engine import AllocationEngine

engine = AllocationEngine(data_dir="engine_data")
engine.load_data()

engine.step1_sku_mapping()      # 运算SKU映射
engine.step2_decay_weight()     # 时间衰减加权
engine.step3_seasonal_factor()  # 季节因子
engine.step4_self_ratio()       # 自身占比
engine.step5_benchmark()        # 基准占比（含 k_cat 收缩）
df_results = engine.step6_final_ratio(demand_qty=3000)   # 趋势调整 + 最终占比 + 落货量

for name, ok, msg in engine.self_check(df_results):
    print(f"[{'OK' if ok else '!!'}] {name}: {msg}")
```

常用覆盖项：

```python
engine.params["alpha_trend"] = 0.5
engine.params["norm_method"] = "proportional"
engine.k_cat = 12.0
engine.seasonal_categories = ["庭院、草坪与花园"]
```
